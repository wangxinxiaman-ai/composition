# 建立前端自动调试反馈机制

**您的指令非常明确**：不要瞎猜，要通过调试机制解决问题。
由于我无法直接访问您的浏览器控制台，我需要构建一个机制，让前端把错误信息“告诉”我（或者至少暴露出来让您能反馈给我）。

**方案：自动化错误回显与自我诊断**

1.  **增强前端 (`home.html`)**：
    *   **捕获原始响应**：在 `fetch` 拿到 `text()` 后，完整保留下来。
    *   **可视化诊断**：如果 JSON 解析失败，**不要只报“格式错误”**。
    *   而是直接在页面上（提交按钮下方）创建一个红色的 `<pre>` 区域，显示：
        *   **状态码**：`resp.status`
        *   **响应长度**：`rawText.length`
        *   **关键片段**：显示响应的**前 200 字符**和**后 200 字符**。
        *   **正则匹配结果**：显示正则到底匹配到了什么（是 null 还是别的）。

2.  **自我修复尝试**：
    *   如果发现响应里包含 `___JSON_START___` 但提取失败，尝试手动清洗字符串（去除不可见字符）。

**这一步的关键价值**：
一旦我部署了这个版本，您再复现一次错误。页面上会**直接打印出**后端返回的内容片段。
比如，如果显示 `<html>...504 Gateway Time-out...</html>`，那说明心跳没拦住网关超时。
如果显示 `Error: ...`，说明后端脚本报错了。
如果显示 `<!-- heartbeat --> ... {"key":...}` 但解析不了，说明是格式微瑕。
