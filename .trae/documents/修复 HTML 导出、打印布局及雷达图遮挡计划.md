# 修复 HTML 导出、打印布局及雷达图遮挡问题

## 1. 修复 HTML 导出后其他内容缺失
*   **问题原因**: 之前的导出逻辑 `cloneNode(true)` 复制了 DOM，但 `init()` 函数会在页面加载时运行。由于导出的 HTML 中没有 `localStorage` 数据，`init()` 可能会尝试渲染空数据或报错，导致页面被清空或无法正常显示。
*   **解决方案**:
    *   在导出的 HTML 中注入静态数据 `window.DATA`。
    *   修改 `script` 逻辑，移除或跳过依赖 `localStorage` 的 `init()` 部分，改为直接调用 `loadData(window.DATA)` 或类似的渲染逻辑。
    *   确保导出的 HTML 是一个完全独立的、包含数据的静态页面。

## 2. 优化 PDF 导出布局（雷达图与维度评价）
*   **问题原因**: 尽管之前合并了卡片，但雷达图高度可能仍然偏大，或者分页符 (`break-inside`) 设置导致了强制换页。
*   **解决方案**:
    *   在 `@media print` 中，显式设置雷达图容器高度为更小的值（如 `250px`）。
    *   确保合并后的卡片 (`.card`) 及其内部元素允许在内部换页，或者更紧凑地布局以避免换页。
    *   检查并移除可能导致提前换页的 CSS 属性。

## 3. 修复雷达图顶部被遮挡
*   **问题原因**: 雷达图的 `radius` 设置为 `62%`，但顶部标签（如“立意”）加上分数后高度较高，超出了 Canvas 的绘制区域。
*   **解决方案**:
    *   微调 `radar.center` 垂直位置，将其下移（例如从 `50%` 改为 `55%`）。
    *   或者稍微减小 `radar.radius`（例如改为 `58%`）。
    *   或者增加 `grid` 或容器的 padding，给顶部留出更多空间。最简单有效的是下移中心点。

## 执行步骤
1.  **修改 `downloadHTML`**: 完善脚本注入逻辑，确保导出后直接渲染数据而不依赖 `localStorage`。
2.  **修改 CSS (`@media print`)**: 进一步压缩雷达图高度，确保紧凑。
3.  **修改 ECharts 配置**: 调整 `center` 为 `['50%', '55%']` 以修复顶部遮挡。
