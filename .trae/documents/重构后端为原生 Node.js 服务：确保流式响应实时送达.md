# 确诊：响应缓冲 (Buffering) 导致心跳失效

**诊断**：
您确认是 **1分钟报错**。这铁板钉钉是 **网关超时**。
这意味着我们发的“空格心跳”**并没有**被网关收到，或者没被浏览器收到。
**原因**：Express 或者 Node.js 的 HTTP 模块默认有 **Nagle 算法** 或 **内部缓冲**。数据太小（一个空格），它就攒着不发。网关在那边傻等，等到 60s 没数据，直接咔嚓。

**解决方案**：
1.  **加大心跳包**：别发一个空格了，发 **1KB 的空白注释**。这样能强制缓冲区刷新。
2.  **禁用 Nagle 算法**：`socket.setNoDelay(true)`。
3.  **原生 HTTP**：还是坚持换回原生 HTTP，因为它更容易控制底层 Socket。

**执行计划**：

1.  **重写 `server.js` (原生 HTTP 版)**：
    *   移除 Express。
    *   在 `req.on('end')` 后，立刻 `res.writeHead(200, headers)`。
    *   **关键**：`res.write('<!-- padding ... -->')`，发一段足够长（比如 2KB）的废话，确保冲刷缓冲区。
    *   **循环**：每 10 秒发一次 2KB 的废话。
    *   业务逻辑完成后，发 JSON 字符串。

2.  **前端 (`home.html`) 适配**：
    *   之前改的 `rawText.trim()` 依然有效，因为 `<!-- ... -->` 也是文本，只要最后 JSON 格式是对的就行。
    *   **微调**：为了防止 JSON 解析失败，我们可以在 JSON 前后加个特殊标记，比如 `___JSON_START___` 和 `___JSON_END___`，前端提取中间的内容。

这样绝对能把网关“骗”过去。网关一看：“哇，一直在传数据（虽然是废话），连接是活的！”
